# 《國王戰爭》戰鬥 UI V3 全面重設｜研究、設計、實作與驗收

**日期：2026-11-15**  
**分支：`feature/compact-battle-ui-redesign-20261115`**  
**審查：Draft PR #10 https://github.com/YEYIEN/king-war-online-full/pull/10**  
**版本範圍：戰鬥中單一視窗 UI，不改房間、配對、伺服器戰鬥、卡牌能力與新手教學的核心操作合法性。**

## 一、使用者問題與程式診斷

使用者回饋目前戰鬥 UI 不方便、資訊過多且需要一直捲動畫面。檢查最新版 `client/src/main.jsx`、`style.css`、`design-system.css` 後，確實存在：

1. 相同國王/HP資訊同時出現在玩家摘要、目標玩家控制與戰場周邊；單一畫面存在大量重複狀態。
2. 每個戰場、手牌、魔法/紀錄、規則/相剋佔據多個垂直區塊，手機長頁讓玩家須在「我方兵種 → 敵人 → 手牌」間反覆滑動。
3. 舊 CSS 累積多層媒體規則及高優先級覆寫，不利局部修改；部分每次渲染的紀錄與教學說明對競技狀態不是必要資訊。
4. 兵種效果若被直接隱藏而沒有明確可叫出的資訊入口，會降低策略判斷品質，因此不能單靠「全部縮小」解決。

## 二、查閱的設計依據

- Nielsen Norman Group：**Progressive Disclosure**，讓常用資訊與操作首先出現、低頻設定和說明按需顯示；避免每次都要求玩家掃描完整規則。https://www.nngroup.com/articles/progressive-disclosure/
- Nielsen Norman Group：**Ten Usability Heuristics**（2024 review），顯示系統狀態、使用者可隨時取消、辨識勝於回想、去除與當下任務無關的元素。https://www.nngroup.com/articles/ten-usability-heuristics/
- Interaction Design Foundation：**UI Design**，控制項應靠近所操控的物件、即時回饋、在不同裝置使用適合的資訊階層。https://assets.interaction-design.org/literature/topics/ui-design
- NN/g：**Help and Documentation**，非必要說明應在需要時由使用者開啟，而不是佔據主要操作畫面。https://www.nngroup.com/articles/help-and-documentation/

這些是普遍可用的介面原則，**不是專門驗證《國王戰爭》實際完成率的使用者研究**；仍須真人對戰驗收。

## 三、新介面的實際資訊架構

### 畫面固定結構

```text
┌──────────────────────────────────┐
│ 回合／倒數          [結束][規則][紀錄] │
├──────────────────────────────────┤
│ 我方國王 HP  │ 對手A HP │ 對手B HP │
├──────────────────────────────────┤
│ 敵方戰場：兵種卡橫向排列／可點擊       │
├──────────────────────────────────┤
│ 我方戰場：兵種卡橫向排列／可點擊       │
├──────────────────────────────────┤
│ 當下操作：部署、選敵、攻擊或施法提示     │
├────────────────────┬─────────────┤
│ 兵種手牌（水平滑動） │ 魔法手牌         │
└────────────────────┴─────────────┘
```

- 預設**不顯示長篇教學提示、重複玩家摘要、獨立目標下拉選單、相剋牆與長篇戰鬥紀錄**；功能仍由「規則」「紀錄」「顯示提示」按需開啟。
- 玩家 HP、敵人 HP、敵方/我方場地、主手牌、魔法、回合操作保留在同一競技視窗。
- 多人局可直接按上方敵方「目標籤」切換對手，且**切換對手不會清空既選定的攻擊者**；對手的手牌與魔法數量照舊只顯示公開的張數。
- 選中的攻擊者顯示在當下操作狀態列，並保留「取消選擇」按鈕。
- 敵方步兵守衛時的國王攻擊禁用，依原本伺服器規則，不新增任何作弊式「最佳攻擊建議」。
- 敵方國王效果有獨立「?」詳情按鈕；**每張場上兵種也有獨立 i 詳情按鈕**，避免隱藏詳細卡面後迫使玩家記住所有特性。
- 魔法選法師／目標／確認流程維持原伺服器動作，但改成**中央聚焦操作面板**，不占滿整頁的空間。
- `結束回合` 按鈕固定為工具列第一順位、優先可見。
- 320–430px 手機以單頁**不需垂直尋找主要區塊**為測試目標；兵種太多時採**區塊內水平滑動**，並非聲稱五張場上卡與九張手牌在320px能同時完整展示所有細節。

### 畫面精簡與代碼變動

- 新增獨立 `client/src/combat-v3.css`，只套在戰鬥頁 `.kwCombatV3`，避開大規模修改登入/大廳/結算 CSS。
- `client/src/main.jsx` 改建 `kwBattleFrame`，將 HP 列、敵我戰場、提示與手牌透過 CSS Grid 配成視窗範圍內的主流程。
- 刪除重複 `PlayerSummary` 元件及玩家統計 DOM、舊目標選擇區、常駐相剋/紀錄區，保留規則和紀錄的既有彈窗入口。
- 所有場上兵種效果只在請求時開啟詳情，不直接塞入每張小卡造成滿版文字。
- 保留專屬教學進度及其必要文字；新手教學為學習場景，允許正常垂直閱讀，不將競技場單畫面限制錯套到教學。

## 四、功能保留及不應誇大的地方

- **無玩法變更**：不更動抽牌、卡牌、施法、兵種攻擊、國王攻擊、AI、房間/Socket.IO event、先後手補償研究規則。
- **保留視覺線索**：HP、牌數、戰力、已行動狀態、步兵守衛與回合控制；長描述由「卡牌能力詳情」按需顯示。
- **風險**：小螢幕的牌堆需橫向滑動，有些詳細說明需多按一次；此為單畫面與可讀性之間的刻意取捨。
- **人工驗收缺口**：桌機/真實手機使用習慣、視覺舒適度、單手操作、實戰誤觸與多人5人局的選敵時間，仍需要真人資料。

## 五、自動驗收與上線規則

新增 Playwright 檢查：
1. 手機 320、375、390、430px 下無全頁橫向溢位；
2. 遊戲 `main`、核心戰鬥 grid 無不必要垂直捲動；
3. HP列、敵我場地、當下操作提示、手牌均在可視高度內；
4. 新手完整九步（兩回合），一般房間與 AI 對戰未破壞；
5. 既有 Node/Socket.IO、依賴安全審查、建置與發布門檻仍需通過。

**本次只在 Draft PR #10 交付**；尚未合併 `main`，未部署 Render。正式發布前應依 CI 最新提交 SHA 與真人實戰查看畫面，再由使用者決定上線。

## 六、下一輪改進

- 真機測量初次出牌、尋找手牌、選攻擊者、選目標、施法所需時間及誤觸率。
- 多人5人局的國王資訊列是否仍足夠辨識；必要時優先顯示現選對手與可展開對手列表。
- 若重複的視覺覆寫仍造成樣式不穩，逐頁清理舊版 `style.css`（目前仍超過70KB），但不可不帶視覺回歸測試就大規模刪除。
- 新手教學保留操作引導；正式對戰將輔助資訊收起，不自動彈出妨礙玩家思考的考題或指示。
