**日期：2026-11-14｜研究分支：`feature/game-experience-redesign-20261114`｜Draft PR #5｜不包含正式發布批准**

## 一、基準與問題

本階段承接第一輪 `docs/optimization-closure-report-2026-11-14.md`：
- 雙人困難先手：原規則 406/600 (67.67%)，先手休戰 + 後手額外 1 牌 343/600 (57.17%)。
- 五人困難危機嚴格翻盤：背水一戰開關皆 5/425 (1.18%)；**先排查是否有使用該機制，不能推定效果本身無效**。
- 四人中等路易十四：53/476 (11.13%)；跨敵人選最佳魔法目標的早前 A/B 有反向副作用，正常預設仍關閉。

以上為 AI 對 AI 模擬的條件性結果，不是真人公平性估計。

## 二、本輪實作

1. `server/ai-strategies.js`：只有在 **normal 難度**、國王為路易十四、無場上法師且沒有魔法手牌時，`louisMageSetup` 實驗旗標會對部署法師加 18 分；保留其他難度及其他國王既有優先序。
2. `server/index.js`：將 `louisMageSetup` 只接入無頭模擬參數與房間設定讀取，預設 `false`；正常房間建置與既有 UI 不新增該選項。
3. `tests/louis-mage-setup.test.mjs`：驗證預設不變、實驗加分只作用於指定條件。
4. `scripts/second-phase-louis-ab.mjs`：以三組固定種子比較四人 normal 的控制組和法師先置組，輸出路易十四勝率、危機翻盤、局長及 completed。
5. `scripts/second-phase-diagnostics.mjs`：把雙人公平開局的「首輪先手禁止主動攻擊」與「後手額外一張兵卡」拆為四組；五人 hard 另檢查背水一戰的 assault/defense 實際使用次數、危機勝場。
6. `.github/workflows/second-phase-balance.yml`：新增可重現 CI 工作及 JSON artifact，使用 Node 24、`npm ci`、`npm test`、`KW_SIMULATION=1`。

**驗證狀態**：變更已提交測試分支；GitHub Actions 當下正排隊。數值 A/B 結果及新一輪全套驗收尚未取得，故**未宣告勝率提升或第二階段平衡完成**。

## 三、下一輪機制與 AI 候選案（尚未修改正式預設）

| 問題 | 候選措施 | 主要副作用檢查 |
|---|---|---|
| 雙人先手偏差 | 分開測先手和平首輪、後手 +1 兵卡，再比較二者聯用；後續可測後手抽二選一換牌，而非單純增資源 | 國王配對×座位、平均局長、先手率是否逆轉、路易十四是否更弱 |
| 五人困難翻盤 | 先量測背水一戰實際觸發與使用次數，釐清是「不可用」、「AI 不用」或「用後無效」；之後考慮低血量減少自傷（2→1）、防禦盾存續至下一次自身回合、限定一次急援；一案一變項 | 回合拖長、連鎖無限復活、領先方遭不合理懲罰、強者利用觸發條件 |
| 四人路易十四 | 本輪先測法師引擎啟動（+18 選牌評分）；若未改善，測條件性優先保護法師或施法後攻擊序列，而非直接疊國王抽牌 | 其他國王勝率、法師卡壟斷、施法效率、魔法後續王傷害 |
| AI 魔法時機 | 當敵方仍有步兵而魔法可清除最後守衛、且己方尚有可攻擊兵種時，優先考慮戰術轉換；以隔回合交易/王傷量測，不用「造成狀態變化」作效益替代 | 三／四／五人局交叉檢驗，避免只優化單一場景 |

## 四、正式採用前的衡量與統計規格

- 固定三組探索種子與至少三組**未參與調參的 holdout 種子**。探索階段每條件至少 600 局；進入候選驗收再擴樣至每條件 3,000 局以上。
- 報告每一條件的勝場/有效樣本、Wilson 95% 信賴區間，不能只列百分比。相同種子不一定能保證完整配對，因為策略不同會改變亂數消耗。
- **雙人**：先手勝率優先朝 45–55% 接近；國王×座位配對最少 100 局/格後才判斷個別格子。局長或未完成率不得顯著惡化。
- **五人**：嚴格翻盤率從 1.18% 提升的探索門檻可設 >=3%，但必須同時觀察危機局定義、觸發使用率與遊戲時長；3% 是候選研究目標，不是宣告公平的硬規則。
- **四人**：路易十四以接近 25% 為方向，首個候選門檻 >=17%，不得以削弱其他國王的極端方式達成。五人與三人 normal 亦須保持不退化。
- 另查遊戲 invariant violations = 0、未完成率、對局回合長度、遊戲公平性與 AI 策略是否僅使用可見資訊。
- 多重候選研究須保留獨立測試集，避免挑選噪音最大的「勝利」版本。
