## 1. 專案階段結案摘要

- **玩家端**：改善連線可見性、離線操作安全、連續點擊與未回覆請求處理、結算頁自主離開、手機小尺寸與操作標籤；四階段教學及多難度 AI 體驗在研究版中進一步調整。
- **伺服器與可靠性**：加入封包大小／速率驗證、可配置 origin 政策、房間數量上限、健康探針、遊戲狀態不變量測試；提供選用式加密快照原型，但未等於正式資料庫或雲端多節點持久化。
- **AI**：從基本依規則評分的 AI，擴充成簡單／中等／困難／征服者分層；加強公開資訊隔離、精確可見戰鬥模擬、限深搜尋、國王專屬策略、對手策略驗證。雙人征服者的有界理性攻擊搜尋在測試分支採選擇性開啟；3–5人不無條件套用該搜尋。
- **沙盤與平衡**：找到雙人先後手顯著偏差的有效研究候選，從原先約64–69%的先手勝率，降至困難51.42%、征服者50.25%（各取兩組未重複驗證種子共6,000局）。中等 AI 仍56.12%，不稱全部完成。
- **工程把關**：新增差異化 CI、漏洞掃描、手機瀏覽器測試、研究原始資料與固定種子驗證。現有公開證據支持本輪測試分支具有明確進展；正式使用仍須 staging、真人與跨網路驗收。
- **決策**：**本輪研究／程式交付可以階段性結案；最新優化版不等於正式上線，雙人補償不自動採用，所有國王及卡牌數值未因本輪研究改動。**

## 2. 舊基線 vs 最新版本：實際改了什麼

| 模組 | `main` 程式基線 | 最新優化分支新增或深化的內容 | 已確認效果及限制 |
|---|---|---|---|
| 建房／加入／多人同步 | 原有 Node + Socket.IO、建房、加房、隱藏手牌及回合處理 | 錯誤封包及頻率守衛、房間上限、健康探針、不同連線與玩家隔離回歸測試 | 測試環境驗證；尚未證明正式網路斷線或跨重啟完整可靠 |
| 操作請求及斷線回復 | 已有重連識別，但前端部分路徑仍直接傳送 Socket 事件 | 統一 `requestNow`、離線立即拒絕、同事件進行中去重、5秒ack逾時、連線錯誤/恢復狀態提示 | 減少過期操作與重複點擊風險；**不等於**伺服器端跨斷線的完整 request-ID 冪等性 |
| 結算畫面 | 部分結束流程5秒後自動返回 | 取消強制5秒返回，明確提供自主返回與離開房間處理 | 改善閱讀戰果的可能性；未進行真人操作時間及理解率測試，伺服器仍有終局清理 |
| UI／行動引導 | 既有卡圖、戰場與教學介面 | `design-system.css`、深色與狀態層級、焦點樣式、減少動畫、觸控尺寸、目標可及性標籤；手機320/375/390/430px 嚴格溢位測試 | 自動化 Chromium 可檢驗；尚未完成真實手機／螢幕閱讀器的人為驗收 |
| 新手教學 | 基本教學入口已有雛形 | 在伺服器合法規則下強化部署→施法強化→擊敗敵人→回合結束四階段，納入反饋及因果理解問題 | 測試的是系統流程，**尚未證明新人學會策略** |
| AI 難度 | 初始依單一步驟評分的 AI，難度差異較有限 | 簡單/中等/困難/征服者策略定位、守衛和資源保存、致勝傷害、魔法使用及多人威脅估計 | 改善策略可解釋性；不能稱所有難度已平衡 |
| 征服者／困難專屬 | 初始未有完整的公開資訊戰鬥搜尋與國王策略測試 | 新增 `ai-strategies.js`、`ai-rational-planner.js`；雙人有界搜尋、亞歷山大雙人專屬策略實測有效；公開資訊視圖及計算限制 | 有獨立 AI 對戰證據；3–5人理性搜尋收益不穩，仍採原啟發式 |
| 戰鬥與魔法引擎 | 戰力與結算主要集中於伺服器主檔 | `combat-primitives.js`、`ai-legal-actions.js`、`public-combat-replay.js`；正式戰鬥共用攻擊預覽、魔法場地 immutable preview | 局部兵種攻擊／魔法效果與正式執行器共用；**完整抽牌、法師、被動、跨回合 state-action 模擬尚未完成** |
| 隱藏資訊 | 客戶端限制他人查看手牌，但部分 AI 評分收到完整玩家物件 | 對手公開投影提供可見 HP／國王／場上兵種／公開魔法張數；私有資料毒化測試與公開動作列舉 | 已降低 AI 未來意外讀取隱藏資訊的途徑；不等於完整資訊集合搜尋 |
| 房間資料 | 伺服器記憶體為主 | 選用 AES-256-GCM 加密房間快照、重啟載入原型與匿名賽局統計 | **預設未啟用正式長期存檔**；缺少多實例、備援和資料治理驗收 |
| 可靠性／CI | 先前已有基本測試及部署腳本 | Node/Socket.IO、安全／負載、npm audit、建置、Chromium桌機及手機、遊戲不變量、固定種子與研究工件；PR 過期 CI 取消機制 | 已有多項可追溯成功紀錄；CI的成功不能代替部署與真人驗收 |

### 遊戲內容和規則的版本區分

研究分支曾納入不同王權、魔法、背水與開局實驗，並有房主可選開關；但**不能將那些已經過研究的候選一律寫成正式遊戲預設**。本輪重點是保持國王、兵種、魔法的正式數值基準可比，將尚待採納的平衡調整放在研究旗標中。雙人「4張／6張＋先手首輪禁攻」特別明確仍**只在沙盤測試模式生效**。

## 3. 驗收成果與數據證據

### 3.1 工程測試

- 早期 PR #5 的 `Verify King War fixes`：45/45 Node/Socket.IO測試及桌機/手機瀏覽器冒煙通過；手機當次橫向溢位為0px。其紀錄屬**指定較早版本**，不是所有後續 commit 的保證。
- GitHub Actions 模擬型負載：10/25/50個房間同機 loopback 測試全部完成，50房／100連線時的150次操作 p95 **12.42ms**。**這不是** Render 對外連線的網路延遲或服務承諾。
- 此輪最新 12,800 場驗收工作 [#43680765649](https://github.com/YEYIEN/king-war-online-full/actions/runs/43680765649) 的 `reliability-ui` 與 `ai-diagnostics` 兩項皆 `success`。PR #7 最後有文件性提交；最終 SHA 對應的工作狀態以 Actions 即時頁面為準。
- 依 GitHub 分支檢查，根目錄／前端 production dependency audit、發布闸門與多項 AI benchmark 都有成功紀錄；**目前未完成正式 Render staging 與真人 QA**。

### 3.2 AI 策略能力：正向與負向結果並列

| 對照試驗 | 實測結果 | 應如何解讀 |
|---|---|---|
| 舊雙人貪婪策略 vs 資源搜尋，對困難 AI 各1,500場 | 48.80% → **62.53%** | 一定對手族群下戰術搜尋有效；不是對真人的勝率預測 |
| 新雙人理性有界搜尋 vs 舊征服者，各600場 | 49.50% → **59.83%** | 另有獨立種子的正向優勢，支持研究分支選擇性使用 |
| 新雙人理性有界搜尋 vs 困難 AI，各600場 | 58.83% → **66.83%** | 雙人策略改善，未證明多人相同有效 |
| 困難 AI 亞歷山大雙人專屬規劃，獨立驗證每政策540場／王 | 56.85% → **66.85%** | 特定國王及雙人情境有收益，不應一體套用五王 |
| 征服者的靜態敵王反制，加權後與原版比較 | 獨立雙人52.67%→53.00%（約+0.33百分點），四人可退步 | **未有足夠證據全面採用**，保留控制組 |
| 六種研究部署偏好與後續速攻、防守代理 | 可作壓力測試 | 不能視為真人最優快攻／防守或已完成自我對弈強化學習 |

### 3.3 雙人先後手平衡：最完整的實證成果

94,500場雙人開局探索／校準／新種子驗證／精修研究之後，首選候選為：**先手起始4張、先手首輪不能攻擊、後手起始6張**（原規則起始各5張；正常後續國王抽牌保持原制）。

| 難度，驗證種子兩批合計，每規則6,000局 | 原規則先手率 | 候選先手率 | 差異 |
|---|---:|---:|---:|
| 中等 | 65.75% | **56.12%** | −9.63百分點 |
| 困難 | 69.07% | **51.42%** | −17.65百分點 |
| 征服者 | 64.42% | **50.25%** | −14.17百分點 |

此研究將困難與征服者拉近50%，但中等仍偏先手，且未進行真人試玩。對局平均長度增加約0.6–0.7個**玩家行動回合**，不是實際分鐘數。

追加**29,600場**對抗性沙盤（16,800場20有向國王配對×均衡／速攻／防守、12,800場可疑配對新種子驗證）：

| AI 對抗風格，各2,800場 | 原規則先手率 | 候選先手率 |
|---|---:|---:|
| 均衡 | 64.25% | **49.32%** |
| 速攻偏好 | 63.43% | **50.57%** |
| 防守偏好 | 64.07% | **52.64%** |

**殘餘例外**：秦始皇→路易十四在防守代理下，候選先手率 **56.25%**（新種子800局，95% CI **52.79–59.65%**）。故不能宣稱所有配對都已達到50%。速攻代理本身在候選規則下僅28.50%勝率（對既有征服者），亦不能推論真人最佳快攻已被測遍。

**本段的94,500與29,600是不同研究批次的對局數；合計124,100為「雙人先手專項實驗累計」而非獨立、無重複的玩家樣本數**。其他跨人數平衡研究另有資料，不在此混加。

### 3.4 尚未解決的國王與多人結構問題

- 成吉思汗的征服者多人局勝率在不同人數／難度間變化大，不能僅憑某次高勝率全域削弱被動。
- 四／五人路易十四在中等 AI 常偏弱，而困難表現未必相同；直接提高法師優先部署曾在 A/B 中令勝率下降。
- 五人嚴重危機翻盤率偏低；背水開／關試驗的差異很小，尚未確認能顯著增加可行逆轉路徑。
- 多人座位順序可能存在與雙人相反的偏差；雙人補償不可無條件套用到三至五人。

## 6. 下一次優化計畫（按投入順序）

**階段 A — 線上版本與發布預備（最優先）**

1. 核實 Render 實際部署 commit，建立獨立 staging 與回滾點；用 PR #7 對照 `main` 逐模組決定升級範圍，不直接一次合併全部研究旗標。
2. 完成伺服器冪等、真實斷網/高延遲、重啟恢復、AI CPU/p95負載測試。
3. 通過玩家端桌機/手機真人操作驗收後，提供**非平衡功能**的明確上線候選。

**階段 B — 雙人公平開局真人封測**

1. 以「原制」與「4／6＋先手首輪禁攻」作房主可切換測試條件，公開顯示規則及牌數；收集國王×座位×玩家經驗×對局結果。
2. 特別研究秦始皇對路易十四的前兩回合；檢查法師存活、首個守衛被清除、首次王傷及第二回合優勢。
3. 根據真人的反制策略與選擇自由評估決策，而非只追求統計剛好50%。沒有通過真人封測前不設為全面預設。

**階段 C — 多人平衡、AI 與戰鬥節奏**

1. 對成吉思汗／秦始皇／路易十四分人數及國王配對追蹤資源流、守衛、施法與勝負；優先修錯誤 AI 策略，再測角色數值。
2. 增強征服者的跨回合公開／隱藏資訊推理與多人合理搜尋，配合合理計算預算；未證明增益的策略持續保留控制組。
3. 驗證背水一戰的實際效益、多人席次效應與極端長局；避免同一輪同時改多種規則。

**階段 D — 發布決議與持續觀測**

- 所有候選附「改動前問題→程式修正→測試證據→負面樣本→風險→回滾條件」。
- 必須取得使用者明確批准後，才合併 `main`、部署正式 Render 或啟用長期玩家資料儲存。
- 正式上線後以匿名且有明確告知的遙測觀察操作失敗率、對局完成率、房間恢復、國王×座位、決策延遲及真人試玩回饋；不能把 AI 對戰勝率直接當成真人排名。

## 7. 本次結案決議
