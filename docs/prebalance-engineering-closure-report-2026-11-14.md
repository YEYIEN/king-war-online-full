## 三、重新分析隱患與處置狀態

| 風險 | 嚴重度 | 已完成的防護 | 尚未解除的阻擋 |
|---|---|---|---|
| 離線舊命令重送 | 高 | 統一 unbuffered request；顯示離線狀態 | 需故障注入實測，確認 Socket.IO 重連前後沒有重複執行 |
| 傳輸已處理但 ack 遺失 | 高 | ack 五秒 timeout，提示玩家先檢查局勢 | 需增加伺服器端 request ID／冪等記錄；不能盲目重試 |
| AI 意外使用隱藏資訊 | 高 | 攻擊決策採公開資訊投影，新增毒化隱私欄位測試 | AI 的選敵、施法、國王技能管線仍需改為完整公共視圖 API |
| AI 只會打同一種困難 bot | 高 | tier-vs-tier 對戰矩陣已提交 | 快攻、防守、魔法控制、資源型及誘餌型代理尚未建置 |
| AI 搜尋預測與真實規則不一致 | 高 | 加入模擬確定性/不變量測試 | 尚未抽取正式共用 `state + action -> next state` 純函式，也無跨回合精確重播 |
| AI 搜尋占用伺服器事件迴圈 | 高 | 現有 Conqueror 仍有限深度，未任意擴大 | 需 CPU/記憶體/p95決策時間量測及 worker/時間預算 |
| 小手機版面擠壓 | 中 | 嚴格 4種寬度驗收 | 螢幕截圖人工審查及真實觸控未完成 |
| 結果頁與房間記憶體保存 | 中 | 結果頁可自主離開；離開時通知 server；房間180秒清理 | 結果頁並非永久可讀；必要時改為客戶端局末快照 |
| 規則凍結檢查涵蓋不足 | 高 | 監測國王、牌組、開局、回合、背水一戰部分 | 尚未涵蓋完整攻擊/施法/狀態效果；需與正式規則原文核對 |
| 前端／後端 CI 未驗證 | 高 | 自動化工作與相關測試已提交 | 不可合併、不得聲稱正式階段通過 |
| 真人資料與存取控制 | 高 | 保留預設不落盤，未啟用正式快照 | Render持久化、多實例、安全告知、資料刪除政策仍未核准 |

## 七、續行批次：共用戰鬥核心與 AI 公開資訊動作生成

### 新問題

1. 正式伺服器原本把 `rankValue`、`power`、`effectiveDamage`、`canAttack`、`battle` 混在 `server/index.js`。AI 使用的戰鬥搜尋存在簡化預測，長期難以驗證與正式規則一致。
2. 攻擊候選在 `selectAttackChoice` 前仍由完整 `enemy` 玩家實體生成與打分；先前只在最後一步將對手轉成公開視圖，沒有真正阻止評分前讀取私有物件。
3. 原先缺少矩陣形式的純戰鬥結果與合法動作生成測試。

### 實際解決

- `server/combat-primitives.js`：從原 `server/index.js` 提取**沒有改數值**的戰力、傷害、出手資格與剋制運算，加入不可變的 `previewUnitAttack`。正式 `resolveAttackUnit` 同步呼叫該預覽，消除其自身一份重複的攻擊結果計算。
- `server/ai-legal-actions.js`：從公開戰場欄位列舉可攻擊的兵種與國王目標，檢查守衛步兵與出手資格，保留原本按對手、再按攻擊者的迭代順序。正式 AI 攻擊階段使用公開投影建立動作與計算分數，選定後再透過 live ID 的正式 resolver 驗證並執行。
- `aiStrategicAttackScore` 使用公開的 `magicCount` 而不是對手 `magic` 私人陣列內容。
- 新增 `tests/combat-primitives.test.mjs`（12種兵種×階級組合的兩兩對戰：共144對，含弓兵與狀態案例）及 `tests/ai-legal-actions.test.mjs`（守衛、已行動、已淘汰與投影隱私測試）。
- 規則凍結檢查更新，允許純戰鬥輔助函式抽取，但仍保護原本的回合、卡牌及背水一戰規則區段。

### 修改後可確認結果

上述檔案已提交 Draft PR #7；程式審查確認正式攻擊結算已使用同一個 `previewUnitAttack`，而攻擊候選生成與評分改用公開敵方投影。這個迭代**沒有新的 GitHub Actions 測試通過證據**，不能將此視為完成完整精確模擬核心。

### 重新檢查後的隱患

- `previewUnitAttack` 目前只覆蓋**單次兵種交戰**；尚未包含國王傷害減免、魔法連鎖、卡牌抽取、回合狀態及對手下一回合行為。完整 `state + action -> nextState` 引擎仍待開發。
- 部分 AI 決策（例如選敵、部署、施法、撤回）仍直接讀取伺服器玩家物件；需要逐一改成公開視圖，不能宣稱全 AI 管線已不可能偷看隱藏資訊。
- 目前動作列舉器只供 AI 攻擊使用；無頭模擬仍採正式伺服器整局流程，沒有完整事件重播。
- 待 CI 檢驗 144 組攻擊與手機 E2E，特別防止重構導致攻擊排序／策略選擇變化。
- 即使純戰鬥核心完全一致，也不能因單次攻擊預覽正確就宣告 Conqueror 已具備多回合搜尋。

**續行批次結論：完成可重用精確戰鬥核心的第一步及 AI 公開動作生成；完整模擬引擎、異質策略聯賽與階段0–6的正式結案仍未達標。**
