## 2. 技術驗證證據

- GitHub Actions `Verify King War fixes` run `43605996336`：**44/44 項 Node/Socket.IO測試通過**，Chromium桌面、手機、新手教學、AI操作 smoke 通過；手機橫向溢出0px；根目錄與前端 `npm audit` 所回報的已知漏洞計數均為0。後續新增房間上限整合測試，需以**最新 commit 的 CI 作最終確定**。
- GitHub Actions `Socket.IO multiplayer load validation` run `43606194051`：三種本機 loopback 合成負載均完成、無測試錯誤：
  - 10個房間／20個連線：P95 **6.58ms**。
  - 25個房間／50個連線：P95 **10.86ms**。
  - 50個房間／100個連線：150筆操作 P95 **12.42ms**。
- **注意：** 測試在 GitHub Actions 同機、WebSocket loopback 環境中執行，沒有真正橫跨公網、行動網路或正式 Render 部署；不能推論正式環境容量與可用性達到任何 SLA。
- 選用式加密快照需要 `KW_STATE_DIR` 和64位十六進位 `KW_STATE_KEY`，沒有這兩項就**不應聲稱正式站具有重啟後的資料恢復**。它是單程序最佳努力寫入，不是交易型資料庫。
- 快照及匿名真人資料預設不寫入生產磁碟；正式儲存方案、玩家告知及存取權限仍需要決策。

## 3. 最新遊戲平衡結果與負面發現

### 3.1 現行規則基準（每種情境600局，同組種子）

| 情境 | 實測結果 | 工程判斷 |
|---|---|---|
| 雙人困難、原開局 | 先手406/600＝**67.67%** | 先手偏強 |
| 雙人困難、公平開局候選 | 先手343/600＝**57.17%** | 先手差距縮小，但仍有偏差，不能只據此正式採用 |
| 五人困難、背水一戰開啟 | 嚴格翻盤5/425＝**1.18%** | 問題仍嚴重 |
| 五人困難、關閉背水一戰 | 嚴格翻盤5/425＝**1.18%** | 這批樣本未證實改善 |
| 四人中等 | 路易十四53/476＝**11.13%** | 明顯偏弱，應優先研究 AI 法師與魔法資源策略 |
| 五人中等 | 路易十四**14%**、成吉思汗**29.17%** | 多人難度與國王存在交互差異 |
| 五人簡單 | 平均**60.23**玩家行動回合 | 真人時間仍未實測 |

### 3.2 新增魔法目標搜尋策略的反例

GitHub Actions `Multiplayer spell targeting A-B` run `43606447212`：每個對照情境600局。使中／高難度 AI 在多名對手中搜尋最高分施法目標：

- 四人中等：路易十四 **13.74% → 11.63%**，方向不佳。
- 三人中等：路易十四 **24.02% → 27.93%**，局部改善，但嚴格翻盤勝場 **33 → 23**。
- 五人中等：路易十四 **14.83% → 15.17%**，提升很小，嚴格翻盤勝場 **14 → 6**。
- 其他人數、難度的效果不一致。

**結果：已將新策略設為實驗旗標 `aiMagicTargeting=true` 才啟用，正常預設使用舊策略。** 不能只因行動評分更高就宣稱遊戲更公平。

### 3.3 魔法『有效率』定義尚待升級

現有 `spellsEffective` 只代表施法後觀察到兵種場上狀態變化，多數魔法超過95%屬於預期：每次施法通常就會產生某種狀態變更。**它不是戰術價值、反殺或促成王傷害的證據**。正式調數值前需要追蹤魔法後續的戰場交換、守衛清除與國王傷害。

## 6. 結案意見與發布建議

**本輪可直接執行的工程加固與研究驗證已有成果，但不建議宣告八階段產品全面結案，更不建議直接合併 PR #5 到正式站。**

原因是目前仍有充分證據支持：雙人先手優勢、多人中等路易十四偏弱、嚴格劣勢幾乎無法逆轉。若只憑 CI 測試通過便把所有功能合併，會把「程式能跑」誤當成「遊戲已完全成熟」。

建議：維持 Draft PR #5；依最新 CI 結果修完技術阻斷問題。工程關卡通過後，先在獨立 staging 驗收，再由所有者決定正式部署和真人封閉測試。**沒有真人驗收與正式環境驗證，專案只能稱作本輪工程階段結案，不是正式營運結案。**
