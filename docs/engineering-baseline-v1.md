## 變更類別與回歸邊界

| 類別 | 必須維持的既有行為 | 驗收來源 |
|---|---|---|
| 遊戲規則 | 相同兵種剋制、手牌可見權限、施法判定與合法玩家操作 | Node/Socket.IO 測試、完整規則模擬 |
| AI | 難度只改 AI 自身選擇，不提示或強制玩家 | no-intrusive-ai-coaching 測試、代理對抗 |
| 安全 | 非法封包、冒用連線、無權房主操作正確拒絕並回覆錯誤 | socket-guard、安全整合測試 |
| 資料 | 明確 opt-in、加密、拒絕明文保存隱藏資訊 | room-snapshots、game-metrics 測試 |
| 介面 | 桌面與手機可建房、加入、遊玩、施法、教學 | Chromium smoke及UI截圖 |
| 計量 | 真人與模擬完全分離、國王與座位完賽分母正確 | game-metrics 單元及離線彙整 |
| 發布 | 保持可回復到已驗證版本，不能自動部署測試分支 | Draft PR、部署檢查表 |

## 規則實驗政策

所有可能影響真人遊戲公平性的規則（雙人公平開局、背水一戰、延遲反攻等）必須先做固定種子 A/B，且必須分析國王差異、座位勝率與翻盤率。不因單一數字提升就直接修改正式規則。

## 版本驗收方式

1. 確認新變更有可重現的測試、樣本與分析方法。
2. `npm ci && npm --prefix client ci && npm test && npm run build`。
3. Chromium 桌面／手機／AI／教學 smoke；如有 UI 改動，人工比對截圖。
4. Node 依賴安全掃描（高危漏洞應阻斷正式發布）。
5. 模擬測試與真人效果分別呈報。
6. 由遊戲所有者授權合併及正式部署，部署後再做線上 smoke 與回復演練。

## 已知未達成項目

目前還沒有：正式 Render 上的50房容量保證、正式版端到端跨重啟可靠性、真人 UI 使用性樣本、付費與行銷實證，以及全面法律／美術授權審核。這些不是程式單元測試能自動完成的工作。
