# 《國王戰爭》新手訓練、UI/UX 與程式碼整潔性複查暨修正報告

**日期：2026-11-15｜範圍：Draft PR #7 / `feature/prebalance-hardening-ai-20261114`｜研究測試分支，不影響正式 Render 與 `main`。**

## 0. 本次決策及範圍

- **不需全面推倒重做遊戲 UI/UX**：目前玩家操作架構、房間、對戰場地及伺服器教學已具備可用基礎；更有效的處理是移除多份矛盾教學、修正可及性與操作提示，依真人使用情形迭代視覺層級。
- **新手訓練需要內容與驗收重整**：保留唯一「直接使用正式伺服器合法動作」的四步操作教學；把單一背誦題改成三個概念情境，但不把答對題目稱為已熟練。
- **大量前端死碼可直接移除**：已消除兩份未使用的教學元件、其狀態與操作入口、未使用的動作卡彈窗、假按鈕事件及失效的舊「再玩一次」函式。
- **保留原玩法與安全機制**：沒有修改遊戲規則、國王、兵種、魔法、AI勝率設定及 Socket.IO 協定。
- **不宣稱全面無缺陷**：本輪屬前端程式審查、用例補強及既有 CI；不取代真人試玩、完整無障礙稽核、真實高延遲網路及壓力測試。

### 本輪程式精簡規模

- `client/src/main.jsx`：原檢查時約**78,265字元**；本批主要 UI 清理後約**65,273字元**，減少約**12,992字元（16.6%）**。
- 數字只描述此檔案的**字元差異**，包含新增3題情境問答，**不是效能提升16.6%**，也不能直接推定 JavaScript bundle／下載大小減少相同比例。
- 另修改 `client/src/design-system.css` 的問答按鈕至少44px、鍵盤焦點、教學驗收說明；擴充 `tests/prebalance-ui.test.mjs`。
- **重要修正**：刪除無用程式需同時掃描「傳遞函式本身作為參數」的引用，而不只搜尋 `functionName(`。此次 `canUnitStillAct` 是具體反例；正式程式碼檢查流程應避免再次誤刪。

## 2. 新手訓練設計評估

現行四個正式引導任務：

1. 部署可立即行動的中級騎兵，並比較2 vs 2的換兵結果。
2. 指定初級法師對騎兵施放力量術，將戰力提升至3。
3. 用已強化騎兵擊敗中級弓兵，理解資源先後順序與守衛規則。
4. 正確結束回合，理解下一回合決策與國王勝利條件。

這四步**有實際 server resolver 驗證，不是只換動畫或按下一步**，比保留三套教學更可靠。新驗收附加三個不同情境的知識提取，而不干擾正常玩家對局。

**目前仍欠缺的教學能力：**
- 沒有「移除明確操作提示後的新局面」獨立應用題；現有3題含答案解析，只能測即時概念辨識。
- 沒有教學失誤原因、各步耗時、首次獨立使用魔法成功率的真人資料。
- 尚未實測玩家在手機垂直版面能否一眼看見「現在應該點哪一張牌」，也沒驗證是否因畫面距離導致反覆捲動。
- 完整新手教學瀏覽器 E2E 尚未逐步自動執行，現有 smoke 只確認能看到第一關。

**下次教學優化**：加入一個完全不同、沒有逐步答案的練習局，讓玩家判斷守衛／剋制／行動成本，並記錄前後是否能獨立完成。這應在真人形成性測試中確認困難度，不要只增加制式選擇題。

## 3. UI/UX 重新評估

**判斷：適合迭代優化，不需要全面視覺重製。** 現有版本可保留主要版面邏輯。最有價值的下一輪改善：

1. **P0 真正的行動預覽／取消**：在選目標及確認攻擊時讓玩家看得到自己會攻誰、消耗何種行動；防止網路延遲中重複送出，不能顯示 AI 最佳行動當作提示。
2. **P0 小螢幕資訊階層與可讀性**：把現在輪到誰、我方 HP、可行動兵種與魔法步驟維持在可辨識的位置，請真人用320～430px及實際Android/iOS測試。
3. **P1 國王／兵種／魔法說明一致**：本輪已修正入口與提示，接下來應提供明確的「查看規則」選擇，不再只靠長按。
4. **P1 教學後首局銜接**：引導玩家從受控教學順暢進入正常2人對戰，而不是突然面對全部卡牌與選項。
5. **P2 終局頁及結果保存**：保留自行返回，未來可加入本局關鍵事件與重新挑戰，不讓資料清理時玩家失去戰果。
6. **P2 可及性**：全程鍵盤、螢幕閱讀器、焦點返回、reduced-motion 與非滑鼠輸入驗收。

**避免反模式**：不建議把普通競技局變成會提示「下一步最優解」的教學畫面；保留玩家自己判斷的空間。也不應因主觀覺得舊版花俏，就無依據完全重畫。

## 4. 後續程式架構與重構目標

| 現有風險 | 建議 |
|---|---|
| `client/src/main.jsx` 仍超過6萬字元、同檔負責房間/教學/戰場/魔法/結算 | 下一階段拆成 `components/TutorialCoach`、`components/Battlefield`、`components/PlayerSummary`、`hooks/useRoomSession` 等，**每拆一模組均跑原 CI** |
| `client/src/style.css` 非常長，與 override `design-system.css` 層疊交錯 | 使用分模組 CSS／設計 token，建立視覺 regression screenshots；不要一次大換樣式引起手機退化 |
| 殘留的舊註解與未使用 CSS selector 可能增加維護噪音 | 以 AST／bundler 與畫面截圖交叉確認引用後，分批刪；不能只靠字串搜尋斷言未使用 |
| 目前自動瀏覽器教學測試只驗第一關 | 增加 Playwright 正式教學「部署→魔法→攻擊→結束→三題驗收」完整測試，以及錯誤動作拒絕測試 |
| 舊 action request 在 ack 丟失場景可能重複 | 補 server request-ID 冪等性與故障注入，不把前端去重視為完整保障 |
| 多人 AI、國王能力與平衡仍有未定事項 | 保持先前研究規則不變；此輪 UI/教學工作**不重新調整任何平衡數值** |

## 5. 測試、驗收與尚未解除的阻擋

新增 `tests/prebalance-ui.test.mjs` 的回歸覆蓋：正式教學入口、舊元件清理、三題問答及回饋、國王鍵盤可及性、結束回合 `canUnitStillAct`、失效彈窗移除、手機 viewport 與連線警示。

**靜態回歸測試只是重要的防呆網**，不能代替對完整 JSX 的實際瀏覽器驗證。正式本輪提交的結果須以最新 SHA 的 GitHub Actions 為準，不引用前一 SHA 綠燈直接宣稱新提交通過。若最新 CI 未完成，報告結案標為「已提交、驗收待完成」。

仍然缺乏：
- 逐步教學完成 + 三題驗收的全流程自動 E2E。
- 實際 iPhone / Android、螢幕閱讀器及鍵盤巡航的真人檢查。
- 真實 Render 部署 commit、手機網路/切換頁籤與斷線恢復測試。
- 首次使用成功率、操作錯誤類型與玩家實際學習成效數據。
