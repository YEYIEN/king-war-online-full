## 2. 第七周目交付定位及優先度

### P0｜一套真正能操作到底的 V2 網頁客戶端

1. **唯一正式 V2 操作流程**：建房、加房、選王、開始、顯示當前回合／HP／兵種／私有手牌、部署、選攻擊者、選敵方兵種或國王、保牌、九魔法指定施法者／對象／兵種、五王能力（含亞歷山大攻擊選擇、秦始皇三抽一放底）、超額棄牌、淘汰與共同勝者。
2. 核心操作**不得需要瀏覽器原生 prompt／confirm／alert**；改為頁面內具取消／確認／錯誤提示的可點選狀態機。兼容 2–5 人，**多人施法目標不能用數字輸入**。介面要清楚區分「可操作」「禁止」「等待回應」，符合手機操作。
3. **伺服器仍然是權威**：合法目標、戰力、國王能力、牌庫、回合與手牌隱藏不可由前端自行決定；測試包括錯誤或惡意事件防護。
4. UI 完成之前**不得以展示卡圖掩蓋玩法 P0**。

### P0｜重連與持久化達成封閉測試最低可接受水準

1. 保留目前 60 秒短期憑證重連、token 輪替、舊 socket 撤權、同一玩家手牌私密。
2. **實作受控的 V2 對局存放與重啟後恢復，並驗證**：包括房間、玩家、兵種牌庫／棄牌、私有手牌、目前回合、暫停攻擊／保牌、魔法狀態、國王能力與 token；伺服器重啟後仍可安全恢復，而非只在單程序記憶體。
3. 必須驗證重複回應／斷線競態、舊 token 重放、對手無法查看手牌、玩家過期淘汰以及保牌計次不重置。
4. **實作選擇關卡：** 若無可用且已核准的可靠持久化儲存，僅能將對外範圍降為「單程序、服務重啟會中斷的限時技術封閉測試」；須在遊戲內顯示限制，不能標示可正式發行。是否購買／啟用付費資料服務另需用戶授權。

### P0｜美術資產真正變成遊戲內卡面

1. 對應目前兵種種類 `步兵／刺客／魔法師／騎兵` × `初級／中級／高級`，建立 **12 個可辨識的獨立卡面資產 ID 與資料對應**。每兵種恰有三個不同人物與故事、固定兵種辨識物；初中高各一張，不把一張三聯圖片冒充三張正式素材。
2. 卡圖採已確定的 63:88 Full Art、大角色、柔焦玻璃資訊欄，**插畫與文字／規則數值獨立編輯**。數值從 V2 權威資料取得；沒有核准的能力絕不杜撰。
3. **完成可供封閉試玩的 12 張整合視覺**（可使用明確註明未最終定稿的原創／授權占位插畫，但不能把純色框或提示詞算作已製作美術）。實際完成度要逐張列出「概念」「整合」「美術審核通過」，不得把 12 個 asset ID 稱作 12 張原創插畫已定稿。
4. 最少完成 **一位真正具名且已核准形象的國王**「立繪＋選王卡＋戰場國王資訊框」三件套；其他四位國王可用一致但標明暫代的可見 UI 模板，**必須讓五王均能正常選擇與識別**。沒有核准角色性別／歷史擬人化時不可擅自宣稱正式定稿。
5. 魔法九種至少完成名稱、圖示、目標說明、狀態展示與效果提示，**不把九張高完成度立繪列為第七周目 P0**；若有剩餘資源再提升插畫。真正二進位素材必須可由 V2 測試入口載入，GitHub 文字提示詞不能替代圖片。

### P1｜工程、可維護性與上線準備

- 修復 client lockfile，乾淨環境 `npm ci`（根）與 `npm --prefix client ci` 均成功，停用安裝流程中會掩蓋不一致的 `npm install` 替代方式。
- CI 分層：單元與 TCP、雙人完整 UI、3–5 人、五王、九魔法、重連／重啟恢復、手機和回歸；避免超長單 job 卡住造成整套結果不可判定。
- 視覺資產來源、版本、授權、正式文字與檔案路徑清單；圖片載入失敗時有可辨識的安全 fallback。
- 最少提供開始前的規則與操作說明、錯誤處理、網路掉線提示，讓陌生玩家能完成首局。
- 保留正式 V1 與 `main`，不擅自併入或更改正式 Render 入口；提供可回復版本及封閉測試候選的獨立部署說明。

### 嚴格範圍凍結規則
- **第 2 次後**，不得主動新增規則、兵種或新模式。
- **第 3 次結束時**，若仍無雙人無 prompt 完整對局，立即停止周邊美術細修，集中修復 UI 狀態／Socket 事件結合。
- **第 4 次結束時**，所有新功能開發應停止、只收斂 P0；若仍有未完成的核心新功能，就**不能宣告第八周目只剩驗收**。
- **第 5 次**正式結案，不以 CI 等待或「下一次修完」延長。

## 5. 第八周目只應做什麼（預定）

若上述 P0 在第七周目完成，第八周目原則上 **不再開發新功能或改規則**，只執行：

1. **回歸與實測**：最新 V2 2–5 人完整 Chrome/Chromium 對局，九魔法、五王、重連與服務重啟、非法事件／手牌隱藏、負載／部署演練；邀請不同設備真人組隊，測試初學者流程和手機界面。
2. **內容與美術驗收**：逐張查 12 兵種卡、國王套件、九魔法圖示的縮圖辨識、文字錯漏、規則對應、來源／權限與正式／暫代標示；必要時只修錯誤和裁切，不新開角色設計方向。
3. **封閉版發布演練**：依 `docs/release-runbook-v1.md` 執行備份、部署、回復、故障告知、隱私／資料安全檢查；**正式合併 main、正式 Render 切流量及平台上架必須另獲所有者明確批准**。
4. **Go/No-Go**：零個未解決 P0 才能考慮公開；若仍有 P0，結論是 **No-Go**，不得把未完成的功能稱為已發布。

**不安排於第八周目的工作：** 新兵種、新魔法、新王、全面角色重設計、排名／賽季／好友系統與平台功能擴張。若第七周目未能完成核心 P0，第八周目不得假裝只是 QA，須在第一次驗收時判為「未達可收尾門檻」，並由使用者明確決定調整範圍／期限。

## 6. 尚不屬於網頁封閉測試版的正式發行條件

依總體發行計畫，若目標是 **Steam／Google Play 對外公開發行**，還需要跨部署持久化保證、完整安全／個資政策、帳號及其刪除規範（若有帳號）、AAB／Windows 安裝與平台政策、至少一輪外網真人與多裝置高負載、營運回滾與持續監控。**本第七／八周目排程未提供能保證平台上架的證據。** 本階段以「具完整功能的 V2 網頁版封閉測試候選」為合理且可驗收的里程碑。

## 7. 管理與結案制度

- 最多 **5 次開發對話**、最多 **3 次必要中斷**，兩者不混計；本計畫書的修訂不計為第七周目開發對話，開始執行才算 1/5。
- 每次實作前先讀 GitHub 最新檔與 HEAD；不憑前次摘要。開始／繼續／執行表示**當次就要用工具完成實際修改／測試**，不能只回覆計畫。
- 每次結束固定報告四分類：**已驗收／已修改未驗收／未完成／阻礙**；附 commit、GitHub Actions job/step、具體測試結果。
- **第 4 次**必須建立階段驗收紀錄；**第 5 次**當次建立正式結案報告，達標或失敗都結案，不展延。
- 在整體 P0 回歸未通過前不得刪 V1、改 `main` 或擅自切換正式入口；未經所有者許可不得啟用付費部署／資料庫／平台服務。
- **提交成功≠自動測試通過；測試通過≠多瀏覽器遊玩通過；多瀏覽器通過≠外網真人與正式發行驗收。**
